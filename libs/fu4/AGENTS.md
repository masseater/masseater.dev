# @r_masseater/fu4

This workspace is a linter for GitHub Actions workflows. The core is written in Rust (`native/core`) and called from TypeScript through a napi addon (`native/node`). Its settings go in `fu4` in vite.config.ts. Build the addon with `vp run native`; the tests depend on that task.

Rules return the same results as actionlint. `native/core/tests/fixtures/actionlint/` holds fixtures and expected results taken from actionlint; do not edit them by hand. Check that `cargo test -p fu4-core` matches them all, and list any that do not match in `actionlint-known-failures.txt` with the reason.

`run:` scripts are checked with tree-sitter-bash instead of calling shellcheck, and give the same results as shellcheck. The expected results in `native/core/tests/fixtures/shellcheck/` come from shellcheck 0.9.0 run with the same arguments as actionlint; do not edit them by hand. When you add a check, add its SC code to the targets in `shared/shell/conformance.rs`.

zizmor's audits are ported in `features/audit_workflow` on top of zizmor's published crates, and return the same results as zizmor. `native/core/tests/fixtures/zizmor/` holds zizmor's test-data and the expected results in `expected.json`. The expected results come from zizmor 1.32.0 run with `--offline --persona auditor`; do not edit them by hand. Audits that query GitHub are checked against the fake GitHub that `online.rs` starts locally.

`native/core/data/` is generated by `vp run generate-data` from GitHub's docs and schemas and from the zizmor repository; do not edit it by hand. Give Rust code tracing spans. When `OTEL_EXPORTER_OTLP_ENDPOINT` is set, the spans go under the caller's trace.
