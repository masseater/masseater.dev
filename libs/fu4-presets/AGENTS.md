# @r_masseater/fu4-presets

This workspace holds the official fu4 rule presets: `actionlint` for actionlint's checks (`features/check-workflows`) and `zizmor` for zizmor's audits (`features/audit-workflows`), selectable per concern. It uses only the rule API of `@r_masseater/fu4`, so it ships as plain TypeScript with no native code.

The rules return the same results as actionlint, shellcheck and zizmor. The conformance tests compare them with fixtures and expected results taken from those tools: `src/app/fixtures/actionlint/` (actionlint 1.7.12), `src/shared/shell/fixtures/shellcheck/` (shellcheck 0.9.0 run as actionlint runs it), `src/shared/shell/fixtures/shellcheck-upstream/` (scripts from ShellCheck's own unit tests, which stay under ShellCheck's GPL-3.0 and out of the published package) and `src/features/audit-workflows/fixtures/` (zizmor 1.32.0 with `--offline --persona auditor`). `src/features/audit-workflows/fixtures/zizmor-tests/` holds zizmor 1.32.0's own integration tests as they are; the test reads each invocation and the findings in its snapshot, and runs it against the same inputs. Do not edit the fixtures or expected results by hand; list an actionlint fixture that does not match in `src/app/fixtures/actionlint-known-failures.txt`, and a zizmor test in `src/features/audit-workflows/fixtures/zizmor-tests-known-failures.txt`, with the reason. Audits that query GitHub are tested against a fake `fetch`, and must never reach GitHub from a test.

`src/shared/data/` is generated by `vp run generate-data` from GitHub's docs and schemas and from the zizmor repository; do not edit it by hand.
