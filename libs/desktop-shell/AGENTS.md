# @masseater.dev/desktop-shell

This workspace holds the window and app behavior shared by the Tauri desktop apps.

It also holds the access token the desktop apps share to serve MCP on the user's own PC, and the local MCP server behind a bearer token.

Every app built on it records traces in `telemetry/traces.jsonl` in the app's log folder, one OTLP JSON batch per line, the format the OpenTelemetry Collector file exporter writes. Tauri's own tracing gives a span for each IPC command, window and protocol request without code in the app. Spans from the app's code at info level and above go to the same file. The screen sends OTLP/HTTP JSON to `otlp://localhost/v1/traces` and `/v1/logs` (`http://otlp.localhost/...` on Windows), and screen logs go to `telemetry/logs.jsonl`. desktop-telemetry starts the sending in each screen, and the app needs `otlp: http://otlp.localhost` in its `connect-src`. Every desktop app adds `telemetry_plugin()`, through `builder` or by hand, and wraps its invoke handler in `traced_commands`, which starts an `ipc.invoke` span in the trace named by the request's `traceparent` header and links it to Tauri's own IPC span. When a file passes 64 MiB, the next start moves it to `traces.1.jsonl` or `logs.1.jsonl`. A batch from the screen above 4 MiB is refused, and so is every batch from the screen once its file has passed 64 MiB, until that next start.

Apps check for an update when they start. When one is found, they download it, ask the user, then install it and restart. Each app needs `plugins.updater` in `tauri.conf.json` with its public key and the feed `https://github.com/masseater/masseater.dev/releases/download/<name>-updater/latest.json`, plus `createUpdaterArtifacts` in `tauri.release.conf.json`. The `updater-key` task makes the signing key in the `<name>-release` environment and prints the public key. Publishing then writes the feed with `updater-feed`.
