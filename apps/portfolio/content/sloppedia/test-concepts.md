テスト概念の名称と担う領域は、ソフトウェアテストで使われる概念の名称と、それぞれの概念が対象とする範囲との対応を整理したものである。テストの用語は統一されておらず、名称の指す範囲が人によって揺らぎやすい。とくにUIテストとE2Eテストは同一視されることが多い。本項目の整理は、主に『[E2Eテスト大全](/sloppedia/e2e-test-taizen)』が既存の理論から整理した定義に基づく[^kuniwak]。

## 層の概念

テストの層を分ける概念は、検証の対象とする範囲の広さで区別される。

| 名称       | 担う領域                                       | 主に担う検証                                     |
| ---------- | ---------------------------------------------- | ------------------------------------------------ |
| 単体テスト | 1つのコンポーネントの内部                      | 分岐網羅や境界値分析などの論理的正確性           |
| 結合テスト | コンポーネント同士の接続部                     | 前段の出力仕様と後段の入力前提の整合             |
| E2Eテスト  | 利用者のインターフェースから永続化層までの全体 | 結合バグの検出、忠実度の検証、性能と使用性の確認 |
| UIテスト   | UIの描画と操作                                 | 表示の差分、コンポーネントの操作イベント         |

UIテストとE2Eテストは重なる部分があるが、同義ではない。UIカタログ上で状態の組み合わせを描画し、スクリーンショットの差分を検出するVisual Regression Testingは、バックエンドや永続化層と結合していないため、UIテストであってE2Eテストではない。逆に、公開APIへリクエストを送って永続化層への反映を検証するテストは、UIを一切操作しなくてもE2Eテストである。境界を決めるのは、操作する対象がUIかどうかではなく、端から端まで結合していることである[^kuniwak]。

## E2Eテストの内部分類

E2Eテストは、操作の選び方によってさらに分類される。機械的な規則やモデルに基づいて操作を選ぶルールベースの手法と、人やAIの判断や経験則に基づいて操作を選ぶ非ルールベースの手法がある[^kuniwak]。

| 名称             | 分類           | 入力                           | 担う領域                                                       |
| ---------------- | -------------- | ------------------------------ | -------------------------------------------------------------- |
| 例ベース         | ルールベース   | 操作と表示確認の系列と期待結果 | 目的の操作が完了できるかという活性違反の検知が中心             |
| グラフベース     | ルールベース   | 状態遷移モデル                 | 活性違反、安全性違反、性能劣化の探索                           |
| モンキーベース   | ルールベース   | システム実装のみ               | クラッシュや未処理例外など、対象に依存しない一般的な安全性違反 |
| ペルソナベース   | 非ルールベース | 想定ユーザーのペルソナ記述     | 認知的負荷の高さや目的達成の困難さという低使用性               |
| エラー推測ベース | 非ルールベース | 過去の欠陥統計や障害履歴       | 過去に経験した類型の活性違反と安全性違反                       |

カバレッジの増やし方も手法ごとに異なる。例ベースはシナリオの数を増やし、グラフベースとモンキーベースは実行時間を延ばして探索を広げ、ペルソナベースはペルソナのバリエーションを増やす[^kuniwak]。

## 検知する欠陥の種類

概念の領域は、検知する欠陥の種類からも切り分けられる。正当性違反は、システムが仕様を満たしていない欠陥であり、受け付けるべき操作を拒否する活性違反と、発生してはならない状態へ遷移する安全性違反に分かれる。妥当性違反は、要求に照らして目的を満たさない欠陥であり、応答や資源消費の悪化である性能劣化と、利用者の手間が大きく目的達成も困難な低使用性を含む。この区別は、Boehmによる検証（正しく作っているか）と妥当性確認（正しいものを作っているか）の区別に対応する[^kuniwak]。

単体テストが主に担うのは正当性のうち論理的な正確性であり、E2Eテストは結合バグのような仕様間の不整合と、性能や使用性といった妥当性の確認までを担う。

## 配置の原則

各概念をどの比率で配置するかについては、テストピラミッドが経験則として知られている。単体テストを最も多く、結合テストを中程度に、E2Eテストを最も少なく配置する。E2Eテストには実行コスト、保守コスト、原因調査の範囲、結果の不確実性、カバレッジの組み合わせ爆発という数理的制約があるため、組み合わせの大部分は単体テストで試し、E2Eテストは主要な業務フローの貫通確認に厳選して使う[^kuniwak]。
