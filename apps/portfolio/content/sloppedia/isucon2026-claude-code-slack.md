いくぜカウシェは、ISUCON2026 に出場したカウシェの3人のチームである。メンバーそれぞれが自分の PC で [Claude Code](/sloppedia/claude-code) を動かし、調査からデプロイ、ベンチマークまでを任せた。エージェントどうしは会話の履歴を共有せず、連絡はすべてチームの Slack のチャンネルで行った。最終スコアは207,039点だった。同社の Zenn の記事は、メンバーの Claude Code が当日の Slack などから下書きを作り、メンバーが手を入れたものである[^kauche]。

## 経過

スコアは10時台に数千点で、15時台に17万点、17時台に20万点を超えた。最後は全台を再起動してから構成を変えずにベンチマークを2回実行し、2回目が最終スコアになった[^kauche]。

14時ごろからは、3人のうち誰もコードとコマンドを書かなくなった。夕方には AI どうしのやり取りも読まなくなり、スコアと順位を見ながら目標と方針を伝える役に回った[^kauche]。

## 方法

### GOAL.md

14時台の後半から、手順を1つずつ頼むのをやめ、Claude Code の /goal コマンドでゴールだけを渡した。リポジトリの GOAL.md の1行目は「ゴール：最終スコア 100 万点」である。当時の最高は16万点前後、1位でも60万点ほどで、届かない値をあえて置いたのは、エージェントが中途半端な点で手を止めないようにするためだった[^kauche]。

GOAL.md には、データの整合性を保つことやレギュレーションの禁止事項など、守ることも書いた。人間が新しい指示を出すと受けたエージェントが GOAL.md に書き足し、ほかのエージェントは pull して取り込んだ。失敗も時刻付きで書き足し、別のエージェントが同じ失敗を繰り返さないようにした[^kauche]。

### 1行の連絡書式

15時半を過ぎると、チャンネルの投稿の大半が AI どうしのやり取りになった。人間が「人が読めなくていい、いちばん速く動ける書き方でいい」と伝えると、エージェントの1つが `CLAIM from=b files=... eta=17:20` のような1行の書式を決めた。先頭の語がメッセージの種類で、残りは名前と値の組である。人間向けの要約だけは、TO_HUMAN という種類にして日本語で書かせ、人間はそれだけを読んだ[^kauche]。

### ベンチマークの分け合い

ベンチマークは1回2〜3分かかり、チームで同時に1本しか実行できず、実行中にデプロイすると失敗する。エージェントどうしで投稿と承認を交わし、ロックを取る仕組みも試したが、13時台から16時までに衝突による失敗が5回起きた[^kauche]。

16時からはデプロイとベンチマークの担当を1つのエージェントに絞り、残りの2つはブランチに push して知らせる形にした。以後、衝突は起きず、担当のエージェントは17時56分までに約40回のベンチマークを実行した。代わりに、担当がベンチマークに追われてほかの2つの変更をしばらく取り込まない問題が出た[^kauche]。

## 評価

チームは、実行の担当と、Slack を読んで次に何を試すかを決める担当は分けるべきだったと振り返っている。16時台に続けて起きた画像の署名の不一致は、3つのエージェントが Slack の投稿とコミットだけで役割を分けて調べ、直した[^kauche]。
